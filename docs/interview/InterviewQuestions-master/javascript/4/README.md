# ['1', '2', '3'].map(parseInt) what & why ?

`['1', '2', '3'].map(parseInt)` 的输出结果为 [1, NaN, NaN]。

因为 `parseInt(string, radix)` 将一个字符串 `string` 转换为 `radix` 进制的整数， `radix` 为介于 `2-36` 之间的数。

在数组的 `map` 方法的回调函数中会传入 `item（遍历项）` 和 `index（遍历下标)` 作为前两个参数，所以这里的 `parseInt` 执行了对应的三次分别是

- parseInt(1, 0)
- parseInt(2, 1)
- parseInt(3, 2)

对应的执行结果分别为 `1、NaN、NaN`。

这段代码的结果会让人感到困惑，因为它输出的不是期望的结果。具体来说，它输出的是 [1, NaN, NaN]。

这是由于 map 方法的工作方式。map 方法会将数组中的每个元素传递给回调函数进行处理，并将处理结果组成一个新的数组返回。在这个例子中，回调函数是 parseInt。

然而，parseInt 函数有两个参数：要解析的字符串和基数（即进制）。在这个例子中，我们没有提供基数参数。因此，parseInt 会尝试根据字符串的开头字符来猜测基数。由于第一个元素是 '1'，因此基数被猜测为 10。因此，parseInt('1', 10) 返回了正确的值 1。

但是，第二个元素是 '2'，但是它被解析为二进制数，因为第二个参数被默认为 2。当 parseInt('2', 2) 尝试解析字符串时，它会发现 '2' 并不是一个合法的二进制数字，因此返回 NaN。

同样的道理，第三个元素 '3' 被解析为三进制数，但是 '3' 并不是一个合法的三进制数字，因此也返回 NaN。

因此，最终的结果是 [1, NaN, NaN]
